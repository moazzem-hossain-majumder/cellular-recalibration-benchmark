# External validation and acquisition record

## US drive with independent measurement boundaries

Chen et al. recorded smartphone downlink and radio measurements during cross-country drives on three US networks. The present evaluation uses one route, Boston to Atlanta (Drive 2), and one alphabetically selected operator, AT&T. The protocol used all five Drive 2 AT&T DL shards, including both day-four clock regions, and the publisher's independently supplied downlink start/end dictionary. The publisher labels the repository CC0-1.0. Commit 782b712599f3710f7d3acff57097af6ca14660ae fixes the release. [Source files and license](https://github.com/NUWiNS/pam2025-multi-carrier-dataset/tree/782b712599f3710f7d3acff57097af6ca14660ae) · [Chen et al., PAM 2025](https://ece.northeastern.edu/fac-ece/dkoutsonikolas/publications/pam25.pdf)

Run `python scripts/validate_nuwins_drive2.py` from the project root. Standard Python downloads absent inputs, verifies the Git blob IDs (LFS pointers commit the CSV byte count and SHA-256), and records file URLs, sizes and SHA-256 digests in `results/external_validation/nuwins_drive2_summary.json`. Forecasts, including abstentions, are in `results/external_validation/nuwins_drive2_forecasts.csv`. There are 212,284 logger rows from four GPS-calendar dates. Five shards carry GPS time, coordinates, application-layer downlink/uplink rates, radio events, NR serving PCI/frequency and LTE channel. The GPS clock aligns with the publisher's interval clock. Device time differs between clock regions and only orders readings tied at one GPS second.

For each whole UTC minute within a supplied interval, issue a persistence forecast if the preceding 60 seconds of the same interval contain a numeric downlink rate. A point forecast uses the last prior observation. Its target is the final measured smartphone downlink rate in the subsequent 60-second bin, truncated at the externally recorded end. The window includes its left edge. It measures an instantaneous logger reading in Mbps. Record empty targets as missing. Calibrate the nonnegative lower bound on the first ten eligible labels from May 13–14. At nominal 10% violation, the rank is ten and the signed error offset is 138.418 Mbps. No predictor fitting, hyperparameter search, outcome-based cohort selection, or test-label recalibration enters this run.

May 15–16 form the test period. Of 380 source AT&T intervals (including a separate August drive), 120 start on the four release dates for this route. The interval file contains **zero May 15 AT&T starts**, despite a day-three downlink CSV. Only May 16 contributes test ticks. Eighteen test intervals contain 36 whole minutes. Of these, 33 have an eligible lag, three trigger abstention and all 33 issued forecasts have an observed target. Eight issued lower bounds are positive. Six exceed the observed rate, giving 18.18% violation, 81.82% coverage, 49.46% supported throughput and 100.09 Mbps persistence MAE. Six of eight positive offers violate. The all-issued violation interval collapses to [18.18%, 18.18%] because all issued outcomes resolve. The subset has one informative held-out date, so it supports neither a day-level confidence interval nor a fleet-wide risk estimate. The measurement roster audits ticks inside supplied experiments only. It cannot count attempted transfers absent from that roster.

## Ireland

Raca et al.'s commercial LTE/5G traces contain measured throughput, signal readings and mobile context. The production ZIP at commit 306d92eba81cb4f1195d8b8eba625666a02a10ec is distinct from the simulated data. The repository includes GPL-3.0, with no separately stated data-ZIP license. Sirhan's version 1 analysis deposit uses CC BY 4.0. The reconstructed published comparison uses 30 overlapping trace partitions. The separate chronological extension uses 11 calibration-pool dates and 16 test dates, with 108,519 strictly ordered next-row cases. Numeric LTE/NR signal availability is measured before imputation. Both ten-label rules give 34.81% observed violation and 71.62% supported throughput. Trace-local next-row targets condition on a recorded next measurement. The independent date count is smaller than the row count, and the release does not define the set of failed unrecorded attempts. Commands, file hashes and exclusions are in EXTERNAL_DATA_PROVENANCE.md and EXTERNAL_SIRHAN_COMPARISON.md. [Raw data](https://github.com/uccmisl/5Gdataset) · [Archived analysis](https://data.mendeley.com/datasets/ncbdm2c36d/1)

## Norway

Riiser et al. recorded TCP streaming downlink bytes, elapsed time, location and monotonic/Unix time on Telenor HSDPA. The publisher provides citation instructions and gives no explicit raw-log license. Content hashes version the 17 bus and 17 metro logs in dataset_manifest.json and metro_manifest.json. The target is the next valid throughput interval computed as 0.008 times bytes per millisecond. The bus cohort has seven dates (three train, two calibration, two test) and 1,278 test intervals. Metro transfer uses the same bus-derived time cutoffs, with 2,893 metro test intervals on three dates. No NR/LTE signal fields exist. This design checks the calibration rule on another generation and checks a route transfer under a common schema. It cannot test Rome's telemetry-specific coefficients. See EXTERNAL_VALIDATION_PROTOCOL.md and CROSS_NETWORK_GENERALIZATION.md. [Simula archive and format](https://datasets.simula.no/hsdpa/)

## Candidates for a subsequent prospective test

DoNext's release removes exact mobile timestamps for privacy. A collection-day key or an independently validated blocking identifier is needed for the same chronological split. MONROE SOMETIME offers downloadable 4G throughput tests. The UMN archive offers commercial 5G experiments. These two candidates have no harmonized endpoint, calendar split or measured result in this study. Additional independently scheduled trips and an audit of missing start records against separate source logs remain priorities. A frozen Rome model also requires matching predictors, units and issue-time availability. ## Budgeted controller extension

The MARUR controller replays both Rome clock suffixes, all three US Drive 3 carriers and Irish active driving downloads. This provides six cohort strata across independent source collections, with correlated dates and shared US driving conditions. The frozen Rome tree transfers to the US and Ireland with the previously documented signal mappings. The Norwegian HSDPA work supports an older-technology lag-only transfer and playback experiment; it is not evidence for a MARUR LTE/5G controller.

Each controller consumes only requested feedback after its horizon ends. The US horizon can end at the publisher's transfer boundary, whereas Rome and Ireland require a full next minute within the recording. Cohorts retain their individual risk and utility metrics. The new recorded/suppressed-response comparison changes what calibration feedback returns, while the evaluator retains every originally measured outcome. No newly obtained dataset or additional physical trip is claimed in this extension.
