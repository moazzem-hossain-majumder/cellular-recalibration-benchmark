# Independent evaluation and published reproduction

The Norwegian evaluation tests the ten-label global rule in another country, technology, operator and period. It transfers the evaluation method. It refits the point predictor because both the available inputs and target differ from Rome. The first route in the public table fixes the cohort without using forecast performance.

Order each log by monotonic time, including the reverse-ordered September 30 log. Use 0.008 × bytes / elapsed milliseconds for decimal Mbps. Retain consecutive, correctly timed intervals with two available lags and a measured next rate. At the completion of the current interval, issue a forecast for the next interval. Use whole UTC dates, chronologically splitting seven dates into three training dates, two calibration-pool dates and two test dates. Only the first ten eligible calibration labels fit the offset. Both persistence and histogram boosting (100 iterations, depth five, learning rate 0.05, seed 42) use the same test intervals. The tree uses two observed lags; persistence uses one. Compute coverage, violations, MAE and supported fraction on 1,278 scored intervals. Dependence within routes and days limits inference. Without radio fields no Norwegian comparison of missingness-specific offsets is identifiable.

Run `python scripts/prepare_ookla_traces.py` followed by `python scripts/validate_clock_and_network.py` from the root with the Rome archives installed. Missing Norwegian inputs are downloaded and verified automatically. Per-forecast records, metrics and exact date lists are under results/external_validation. Regenerate the publication with `python scripts/build_paper_html.py` and `python scripts/validate_manuscript_consistency.py`.

The Irish analysis separately reproduces Sirhan's existing trace split, feature pipeline and one-sided global frontier. It then applies alternative point rules to those same predictions and calibration/test partitions. This estimates paired benchmark differences. It does not independently test a frozen Rome model or the same next-session endpoint. README.md gives the raw-data rerun commands. See EXTERNAL_SIRHAN_COMPARISON.md for nominal and retrospective settings and all trace exclusions.

## Irish chronological missingness extension

Run `python scripts/validate_irish_groups.py` after the raw Irish reproduction creates consolidated.parquet. This separate evaluation uses the two numeric signal fields before imputation, ordered lag/issue/target timestamps within each trace and a persistence forecast. The first eleven dates form the pool and the last sixteen the common test suffix. No trace crosses a date. We report the first ten and the complete calibration pool to reveal limited group support and later shift. Group offsets require nine scores at nominal 0.10. An absent or insufficient group uses the pooled offset. At ten labels both methods gave 65.19% coverage, 34.81% violations and 71.62% supported throughput. At the full pool the grouped rule gave 70.14%, 29.86% and 71.36%, respectively. All point MAEs were 9.05 Mbps. Signal availability means a numeric reading reported by the logger; it does not verify radio attachment or resolve sentinel-like extreme numeric values. This is an exploratory reuse of the Irish recordings, separate from both the published reproduction and the Norwegian data.
