# Archived-trip playback protocol

Before reading outcomes from the nine additional Simula routes, fix the cohort to every report on every route listed by the publisher other than the previously used bus and metro. A file is a recorded run, with multiple files on the same route/date treated as one block for sensitivity. Do not assume route dates are independent. Use the source bus lag-only HistGBM fitted before October 1, 2010 and its ten-label bus offset from the existing chronological split. Freeze these before evaluating all trips beginning on or after the established January 30, 2011 cutoff. No labels from the nine routes tune any parameter. The limited radio schema permits the Norwegian lag model only.

For application impact, replay each trip as a piecewise-constant capacity trace from measured bytes and elapsed milliseconds. At every completed segment choose a two-second video segment from 0.15, 0.3, 0.75, 1.5 and 3 Mbps. Compare last observed interval rate, its bus-calibrated lower forecast, the frozen bus tree point forecast, its calibrated lower forecast, and a constant minimum representation. Choose the largest supported representation, falling back to the minimum. Observe only completed capacity intervals. Start playback after the first full segment. Request continuously, with no buffer cap. No losses, transport feedback, encode variability or request overhead are imposed. End at trace exhaustion and count stall time during a final incomplete request. Report startup delay, stall fraction of post-start wall time, average completed-segment bitrate, complete segment count, total bytes in incomplete segments, and paired route/date effects. Report zero-content sessions separately. Avoid optimizing or pooling test dates to select a winner. A stall reduction accompanied by lower bitrate is a trade-off. This is an offline client simulation under exogenous service, not an observed field treatment effect.
## Additional frozen Rome-tree comparison on Irish drives

Before scoring the tree, take all Irish Download/Driving traces. Restricting to active downloads avoids interpreting a video player's own requested rate as link capacity. Reuse the existing all-application calendar separation from the Irish benchmark; calibrate each model on the first ten earlier eligible driving-download outcomes only. Replay every whole minute inside each trace. A forecast requires a numeric, nonnegative preceding-minute throughput sample. Use the last numeric rate in the next minute as outcome only when the whole horizon is inside the recording. Preserve missing outcomes and empty/no-lag ticks. Map LTE RSRP/RSRQ and NR RSRP/RSRQ with the released units; leave SINR absent since LTE SNR is a different quantity and no NR SINR is supplied. Use outdoor driving, the last pre-issue rate and its age/span. Report all routes and dates; these Irish archives have appeared in earlier project analyses and provide retrospective external evaluation only.
